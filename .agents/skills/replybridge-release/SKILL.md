# ReplyBridge 发布

按用户目标选择下列分支，不默认串行执行全部分支。发布准备不等于获准公开仓库或升级服务器；已有授权持续有效，覆盖范围内连续完成。普通修改不因触及 Docker 文件或版本文字就自动进入部署。

配置和平台验收查阅[使用文档](../../../docs/comment-bridge.md)；构建与数据切换复用[部署文档](../../../deploy/comment-bridge/README.md)及其同目录 Dockerfile、Compose 配置。只读当前分支需要的章节。

部署文档列出的真实链路测试须受本次范围和发送授权约束，不因文档列出就自动执行；其中恢复切换前快照的步骤仅适用于已确认不会丢失新动作记录或造成重放的情形。引用这些步骤时应用下述条件。

## 开源发布准备

- 确认拟公开范围及 Git 状态；没有 Git 时先按文件清单检查，不自动初始化仓库。
- 检查实际发布清单及将公开的 Git 历史（若存在），包括 dotenv、OAuth 文件、Cookie、数据库、日志、备份和历史 `dist/` 包。`.gitignore` 不是已跟踪文件或历史无泄露的证据；发现疑似秘密只报告路径与类别，不输出值。
- 检查许可证、第三方声明、独立构建入口和示例配置是否齐备。未选定许可证时列出必要决策，不替用户选择或宣称已经满足开源条件。
- 公开说明使用仓库相对路径与参数化目标，不包含个人主机地址、SSH 别名、账号、群 ID 或本机用户名。保留对非官方 B站接口及平台能力的准确说明。
- 交付可公开范围、缺项和已验证内容；仅在已获对应授权时创建公开仓库、推送或发布。

## 制品构建

- 从本项目当前源码构建；Go 版本、依赖和应用版本分别核对 `go.mod`、`go.sum` 和命令入口，不将历史包或文档版本视为当前事实。
- 按发布范围运行现有测试和 `go vet ./...`；并发或核心状态变更选择对应竞态检查。只为准备说明文字时不构建。
- 核对目标 OS / 架构、Docker 构建上下文与忽略规则，凭据和数据库不得进入镜像。遵守现有兼容性命名，不顺手改 module、环境变量或 volume。
- 核验制品版本、架构和校验值。需要传输时，校验清单使用目标端可解析的相对文件名；制品构建成功只证明这一阶段完成。

## Docker 升级与回滚

- 变更前确认已授权目标、当前镜像和运行实例、Compose 配置、数据卷及凭据挂载、兼容性和可执行的回滚路径。用 `docker compose ps -q comment-bridge` 获取容器，不猜测自动生成的名称；按目标部署补齐 Compose 文件及 env 参数。
- 预先准备镜像和目标环境后再切换。遵守单实例约束：停止旧实例并确认退出，生成 SQLite 一致性备份及配套 B站凭据备份，核对完整性和任务聚合后再启动新实例。具体命令沿用部署文档；不热拷贝数据库及旧 WAL/SHM。
- 核验容器用户对数据卷和外挂文件的实际读写权限；不要删除数据卷、清空队列或重置失败任务来让健康检查通过。
- 切换后分别确认实际版本、容器状态与重启、数据库完整性和任务状态、飞书连接、平台轮询。真实“新评论 → 飞书通知 → 引用回复 → 平台回复”及点赞检查按本次改动和已有发送授权选择，未执行项明确标注。
- 失败时按预先确认的回滚条件处理。回滚前停止新实例并保留切换后数据库与凭据快照；核对切换后新产生的外部动作。旧备份无法撤销外部发布，存在新动作时不可直接恢复旧状态并重放任务，应先核对并确定避免重复的恢复方式。
- 可恢复旧快照时，数据库与对应凭据一起恢复，且始终仅运行一个实例。不得通过反复重启绕过平台冷却或掩盖失败。

## 交付证据

报告本次实际完成的阶段、版本或制品、验证结果、未核验项及需要时的回滚位置。构建、上传、容器健康和用户真实链路分别描述。必要条件不足只暂停依赖步骤，不重复索取已有授权，也不把计划中的验证写成已通过。
